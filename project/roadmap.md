## 0. 先明确研究问题与成功标准

暂定核心问题：在明确的物理参数约束下，反压缩强度 `ξ` 与自旋交换 `J` 如何改变超辐射相、磁序以及二者共存区域的**可达性和可测信号**？不能把“添加一个二次项”当作创新。已有 [Langheld 等（2025）](https://arxiv.org/html/2409.15082)的 Ising QMC 相图及 A² 补充分析、[Gammelmark–Mølmer（2011）](https://arxiv.org/html/1102.1905v1)的量子 Ising 有限温度自由能，以及 [Leibig 等（2026，预印本）](https://arxiv.org/html/2601.10210v1)的自洽量子链零温相图。

**毕设最低交付**：明确模型与物理边界；可复现 `J=0`、`ξ=0` 两类基准；一套收敛检查充分的参数路径及光/磁观测量；解释其与已有相图的关系；完成规范写作。**更强的论文候选**还需可信的平台约束、前人未直接给出的可达窗口或测量预测，以及独立方法验证。

## 1. 工作模型：先统一符号，再写程序

使用 `ℏ=k_B=1`，`s_i^α=σ_i^α/2`，`S_x=Σ_i s_i^x`。建议统一为下式；`J>0` 表示反铁磁，`J<0` 表示铁磁，先取偶数 `N` 的周期链：

```text
H = ω a†a + Δ Σ_i s_i^z + 4J Σ_i s_i^z s_{i+1}^z
    + (2g/√N)(a+a†)S_x + [D(g)-ξ](a+a†)².
```

这里的 `4J s_i^z s_{i+1}^z=Jσ_i^zσ_{i+1}^z`，可直接与 Langheld 的符号比较，其 `ε=Δ/2`。工作中要分别标出 `D(g)` 的**纯数学示例**（例如 `κg²`）和从实际器件推导的关系；在没有后者之前，不宣称真实无泵浦装置实现了独立静态 `ξ`。

记 `B=ω+4[D(g)-ξ]`。`B>0` 是当前二次光场模型有下界的必要条件。对每一组稳定参数，光子压缩变换给出 `ω_s=√(ωB)`、`g_s=g(ω/B)^(1/4)`；所有平衡态相图必须先与这组变换后的已知模型比较。零温的连续失稳可用自旋横向磁化率初筛；**一级转变必须比较全局能量/自由能**。

| E5 | 写一页论证：已有工作完成了什么、本项目新增什么、为何有物理用途、最强反对意见及回应 | 与导师评估继续、收窄或更换问题；决定及依据写入 `project/decisions.md` |

为每个候选效应填一行：`现象—参数—最近文献及公式/图—压缩映射是否已解释—平台可达性—独立验证—可测信号`。优先研究**物理约束下此前没有定量给出的可达边界**。评估时区分三种结果：

- **已知**：相区或一级边界本来存在，只是 `ξ` 改变了控制路径；作为毕设分析，不宣称新机制。
- **增量**：某个具体平台的稳定窗口、反压缩阈值或实验可读出的联合信号此前未量化；继续交叉验证，评估专题论文。
- **强新意候选**：微观可信的新机制，或有明确突破的实现/测量预测，并有独立证据。不能被单模变换消去是一种可能的创新来源；幺正映射的存在本身也不排除一个新物理实现有价值。投稿判断依赖结果强度，不能只用模型是否可映射决定。

**停走标准**：若所有候选结果都能由已知相图精确映射得到，就完成扎实毕设，不无限扩大参数扫描；若确有强候选，再与导师讨论平台、合作及投稿目标。

建议用 `S_π^z=N⁻² Σ_{ij}(-1)^{i-j}⟨σ_i^zσ_j^z⟩` 衡量有限系统的交错关联，并注明这个归一化和边界条件；在有限系统中直接的交错磁化期望值可能因对称性为零。原光场 `X=(a+a†)/√2`、`P=(a-a†)/(i√2)` 的方差要用原算符求，不能把压缩象 `b` 的光子数直接当成真实可测光子数。

### 阶段 F：条件延伸与写作（并行，时间依具体结果）

**前置条件**：F1–F4 的研究延伸由 E5 选择，最多先做一条；F5 的写作从 A 阶段即可开始。延伸并非毕业验收的自动新增要求。

## 3. 每次计算的记录格式

`results/runs/<日期>-<任务编号>-<短名称>/` 保存同一次计算的参数、日志、数据和初步图；最终核验图放 `results/figures/`。大量生成数据默认不提交 Git，Git 不等于它们已有备份；正式大计算前另外确定这些数据的保留和备份位置。

**配置和索引要能同步**：首次建立运行入口时，在 `code/configs/` 保存小型输入配置并提交 Git；运行目录中的 `params.json` 是实际执行参数的快照。运行摘要与验证状态登记在 `results/README.md`，外部输入与跨运行汇总登记在 `data/README.md`。两个索引提交 Git，实际数据按备份方案保存。当前尚未配置独立数据备份。

产物只保留一个主要位置：外部原始数据 → `data/raw/`；单次仿真原始输出 → `results/runs/`；跨运行加工表 → `data/processed/`；已核查图 → `results/figures/`。不把一套仿真输出同时复制到多个目录。文献解释全部追加到 `literature/reading-list.md`，模型与推导集中在 `theory/` 两份文档，LaTeX 笔记承接有依据的研究叙述。

| 文件或字段 | 最低必需信息 |
| --- | --- |
| `params.json` | `model_version`、单位、`N`、边界与键计数、`ω,Δ,J,g,D,ξ,T`、扫描参数如何生成、基底/压缩表示、`n_max`、求解器容差、随机种子（如适用） |
| `environment.txt` | 实际运行命令、Python/数值库版本、CPU/内存、运行时间；代码提交号及是否有未提交修改，只记录复现所需信息 |
| `summary.json` | 成功/失败状态、本征残差、关键观测量、截断检查和尺寸检查是否完成、误差估计；未算出的值不能填作 0 |
| 数据与日志 | 参数点和原始输出一一对应；中断、未收敛、禁区分别标记；重算生成新记录，不覆盖原始数据 |
| 图与说明 | 生成脚本版本、输入记录、横纵轴单位、尺寸、边界、近似和文献基准；未验收的图留在运行目录 |

每项任务完成时，在 `project/progress.md` 追加一段即可，不新建一批任务卡片：

```text
日期 / 任务编号 / 状态：
输入模型与代码版本：
执行了什么：
产物文件或运行目录：
验收证据及误差：
当前结论能支持到哪里：
失败原因或未解决问题：
下一任务编号：
```

## 5. 用户、导师与 Codex 的分工

- **用户与导师**：确定毕设期限、实际器件/平台、独立 `ξ` 是否有物理来源，以及最终研究深度和论文格式；审核关键物理假设与选题转向。
- **Codex**：维护同一份文献综述及引用库；把公式推导写成可复核的笔记；实现计算和收敛检查；将参数、代码版本、图与论文文字连起来；发现新结果时主动给出“已知/新增/尚未证实”的证据表。
- **共同检查点**：每完成阶段 B、C、D，先看通过标准和错误来源，再决定是否进入下一阶段；关键方向变更写入 `project/decisions.md`。导师意见优先于当前暂定模型。
